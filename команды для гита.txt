# Диагностика: у вас просто не установлен Git

`git` не является командой PowerShell/CMD, потому что Git for Windows не установлен (или не добавлен в PATH). Это нужно исправить первым делом, иначе все остальные команды не имеют смысла.

---

## Шаг 1. Установить Git

### Вариант A — через `winget` (быстрее, Windows 10 1809+)

В PowerShell:

```powershell
winget install --id Git.Git -e --source winget
```

### Вариант B — вручную

Скачайте установщик: <https://git-scm.com/download/win> → запустите → жмите «Далее» везде (по умолчанию всё правильно, включая «Git from the command line and also from 3rd-party software»).

### После установки — обязательно

1. **Закройте терминал** в VS Code (крестик на вкладке PowerShell).
2. Откройте новый терминал: **Terminal → New Terminal** (или `Ctrl+\``).
3. Проверьте:

```powershell
git --version
```

Должно вывести что-то вроде `git version 2.43.0.windows.1`. Если всё ещё «не распознано» — перезагрузите компьютер (Windows иногда не подхватывает PATH до перезагрузки).

### Один раз настроить себя (иначе коммиты не создадутся)

```powershell
git config --global user.name "Ваше Имя"
git config --global user.email "you@example.com"
```

## Шаг 2. Упорядоченный список команд

Выполняйте **строго по порядку**, каждую группу — и проверяйте `git status` между ними. Все команды — в PowerShell, из папки `C:\SchedulerProMax`.

### 0. Убедиться, что вы в правильной папке и это git-репозиторий

```powershell
cd C:\SchedulerProMax
git status
```

- Если пишет **«not a git repository»** — репозитория нет. Инициализируйте:

  ```powershell
  git init
  git branch -M main
  ```

- Если пишет список файлов — репозиторий есть, идём дальше.

### 1. Сделать «снимок» текущего состояния (страховка)

**Зачем:** если что-то сломается в процессе — вы сможете откатиться командой `git reset --hard`.

```powershell
git add .
git commit -m "Baseline: snapshot before refactoring"
```

Если git ругается, что нечего коммитить — значит, всё уже закоммичено, идём дальше.

### 2. Создать `.gitignore` в корне

**Зачем:** чтобы `build_env/`, `__pycache__/`, `dist/` и прочий мусор никогда больше не попадали в коммиты.

Создайте файл `C:\SchedulerProMax\.gitignore` с содержимым:

```gitignore
# Python
__pycache__/
*.py[cod]
*$py.class
*.so

# Виртуальные окружения
build_env/
.venv/
venv/
env/

# PyInstaller
build/
dist/
*.spec

# IDE
.vscode/
.idea/
*.swp

# OS
.DS_Store
Thumbs.db

# Логи и выходные документы
*.log
output_*.docx
```

В VS Code: **File → New File** → сохраните как `.gitignore` в корне проекта.

### 3. Убрать `build_env/` и `__pycache__` из отслеживания git

**Зачем:** файлы останутся на диске (локально всё работает), но git перестанет их «видеть» — репозиторий перестанет раздуваться.

Самая надёжная команда (перечитывает всё через новый `.gitignore`):

```powershell
git rm -r --cached .
git add .
git status
```

В `git status` **не должно быть** строк, начинающихся с `build_env/` или `__pycache__/`. Если есть — значит `.gitignore` в неправильном месте (должен быть в `C:\SchedulerProMax\.gitignore`, а не в подпапке).

Коммит:

```powershell
git commit -m "chore: apply .gitignore, untrack build_env and __pycache__"
```

### 4. Удалить локальную папку `build_env` (по желанию)

**Зачем:** виртуальное окружение удобнее держать вне проекта.

```powershell
Remove-Item -Recurse -Force build_env
```

Создайте новое вне проекта (при необходимости):

```powershell
python -m venv $env:USERPROFILE\.venvs\schedule
& $env:USERPROFILE\.venvs\schedule\Scripts\Activate.ps1
pip install -r requirements.txt
```

### 5. Архивировать старые GUI-файлы

**Зачем:** они не используются, но удалять страшно. `git mv` сохраняет историю.

```powershell
New-Item -ItemType Directory -Force -Path archive\old_ui | Out-Null

if (Test-Path old_ui)               { git mv old_ui archive\old_ui\old_ui }
if (Test-Path new_working_gui.py)   { git mv new_working_gui.py archive\old_ui\ }
if (Test-Path vlad_gui.py)          { git mv vlad_gui.py archive\old_ui\ }
if (Test-Path schedule_app\old_ui)  { git mv schedule_app\old_ui archive\old_ui\schedule_app_old_ui }

git status
git commit -m "chore: archive legacy UI files"
```

`if (Test-Path ...)` — чтобы команда не падала, если файла нет.

### 6. Перенести тестовые данные в `samples/`

**Зачем:** отделить «рабочий код» от «данных для проверки». Структура становится очевидной.

```powershell
New-Item -ItemType Directory -Force -Path samples | Out-Null

if (Test-Path чек)           { git mv чек           samples\check }
if (Test-Path тестирование)  { git mv тестирование  samples\test  }

git status
git commit -m "chore: move test data to samples/"
```

### 7. Рефакторинг `gui.py` → пакет `gui/`

**Зачем:** разбить 900-строчный файл на модули (см. предыдущий ответ).

Это **ручная работа**: создаёте файлы, копируете код, удаляете старый `gui.py`. Git-команды — только после того, как файлы на диске готовы.

```powershell
# 1) Убедиться, что старый gui.py ещё на месте (на всякий случай скопируйте его в блокнот)
Copy-Item schedule_app\gui.py C:\Temp\gui_backup.py

# 2) Удалить старый файл
git rm schedule_app\gui.py

# 3) (вручную в VS Code) создать папку schedule_app\gui\ и файлы:
#    __init__.py, styles.py, helpers.py, loading_dialog.py,
#    excel_loader.py, excel_mixin.py, pages_mixin.py,
#    build_mixin.py, main_window.py

# 4) Проверить, что импорт работает
python -c "from schedule_app.gui import run; print('OK')"

# 5) Если OK — добавить в git и закоммитить
git add schedule_app\gui\
git commit -m "refactor: split gui.py into gui/ package"
```

**Если что-то сломалось** — откат:

```powershell
git reset --hard HEAD~1
```

(вернёт удалённый `gui.py` и уберёт новые файлы; работайте после этого аккуратно).

### 8. Добавить тесты

**Зачем:** защитить от регрессий при будущих изменениях.

```powershell
New-Item -ItemType Directory -Force -Path tests | Out-Null
New-Item -ItemType File    -Force -Path tests\__init__.py | Out-Null
```

Создайте `tests\conftest.py`, `tests\test_filename_meta.py`, `tests\test_docx_builder.py` (код — из предыдущего ответа).

Установите pytest и запустите:

```powershell
pip install pytest
pytest -q
```

Коммит:

```powershell
git add tests\
git commit -m "test: add pytest suite for filename_meta and docx_builder"
```

### 9. Финальная проверка

```powershell
git log --oneline -10
git status
```

Ожидаемо: `git status` — «nothing to commit, working tree clean», а в логе 5–6 осмысленных коммитов.

## Частые грабли (что может пойти не так)

- **`git` не распознаётся после установки** → перезапустите PowerShell/VS Code; в крайнем случае перезагрузите ПК (PATH обновляется при старте сеанса).
- **`fatal: not a git repository`** → сделайте `git init` в `C:\SchedulerProMax`.
- **`git mv` ругается «bad source»** → файла нет; проверьте `Get-ChildItem` и выполните только существующие команды (в скриптах выше это уже учтено через `if (Test-Path ...)`).
- **Кракозябры в именах (`чек`, `тестирование`)** → PowerShell 5.1 иногда плохо дружит с UTF-8. Если `git mv чек ...` не находит файл — переименуйте папки вручную в Проводнике в латиницу (`check`, `test`), потом `git add`.
- **`git commit` требует имя/email** → сделайте `git config --global user.name ... / user.email ...` (шаг 1).

Если после установки Git на каком-то шаге появится другая ошибка — пришлите вывод команды, разберём точечно.
